# Multimodal RAG for Soccer Match Event Retrieval

> ⚠️ **DATA PROVENANCE NOTICE: SYNTHETIC DATA DEMO**
>
> This repository runs by default on **synthetic per-frame tracking data & rendered match video** generated by `src/utils/mock_data_gen.py`. It simulates realistic 2D player/ball pitch trajectories to demonstrate an end-to-end slice without requiring proprietary match footage.
> 
> To run on real Game State Reconstruction (GSR) tracking output, place your per-frame tracking JSON in `data/sample_tracking.json` and set `data_source: real` in `config/settings.yaml`.

## 📽️ Demo Walkthrough (3-4 Example Queries)

When demoing or recording a walkthrough GIF for this project, test these 4 distinct query types in the Streamlit app:

1. **Specific Event Search**: *"Show me when Team A crossed into the penalty box"*
   - *Result*: Retrieves `[00:40 - 00:50]` box entry event and scrubs the embedded player to `00:40`.
2. **Tactical Defending Query**: *"Find turnovers or lost possession in the defensive third"*
   - *Result*: Retrieves `[01:25 - 01:35]` turnover event where Team A lost possession under pressure.
3. **Pressing Sequence Search**: *"When was Team A subjected to high pressing sequence?"*
   - *Result*: Retrieves `[02:10 - 02:25]` continuous pressing spell involving 3+ defenders.
4. **Adversarial / Non-Existent Query**: *"Was there a second yellow card given to any player?"*
   - *Result*: Vector store distance filtering detects low similarity (score $> 1.2$), returning: *"No relevant match events found."*

## 🏗️ Architecture & Component Decoupling

The single most important architectural choice in this system is the **strict decoupling of Event Extraction from the LangChain RAG Pipeline**. This allows swapping rule-based heuristics for deep-learning event models without touching vector indexing or QA synthesis.

```
+-----------------------------------------------------------------------------------+
|                            GAME STATE RECONSTRUCTION                              |
|                           (Frame-Level Player & Ball Tracks)                      |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| STAGE 1: NOISE PREPROCESSING & SMOOTHING (src/event_extraction/preprocessor.py)   |
| - Linear coordinate gap interpolation (up to 8 frames)                            |
| - Continuous possession dwell-time filter (>= 5 frames)                           |
| - Continuous high-press sequence hysteresis filter (>= 10 frames)                 |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| STAGE 2: DECOUPLED EVENT EXTRACTION HEURISTICS (src/event_extraction/heuristics.py)|
| - Pitch Zone Mapping (Defensive, Midfield, Attacking Thirds, Penalty Boxes)       |
| - Passes, Turnovers, Box Entries, Shots on Goal                                  |
| - Simplified Offside Proxy (Frame-window defender line approximation)             |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| STAGE 3: EVENT-ADAPTIVE SEMANTIC CHUNKING (src/rag/chunker.py)                    |
| - Short Events (Passes, Turnovers, Shots): 3-6s tight window                      |
| - Continuous Spells (Possession Spells, Pressing): Natural spell duration (12-25s)|
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| STAGE 4: VECTOR EMBEDDING & INDEXING (src/rag/vector_store.py)                    |
| - Chroma Vector DB + HuggingFace Embeddings (all-MiniLM-L6-v2)                   |
| - Metadata enrichment: timestamps, pitch zones, player jerseys, teams             |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| STAGE 5: LCEL QA SYNTHESIS & VIDEO LINKING (src/rag/qa_chain.py & app.py)        |
| - Synthesizes tactical answers with exact timestamp citations [MM:SS - MM:SS]    |
| - Ffmpeg sub-clip cutting -> Streamlit embedded player playback                   |
+-----------------------------------------------------------------------------------+
```

## 📊 Stress-Tested Retrieval Evaluation

To avoid circular consistency bias, our evaluation suite (`tests/test_retrieval_quality.py`) stress-tests **10 benchmark queries** across 4 categories:

- **Specific Positive Queries** (e.g. *"Show penalty box entries"*)
- **Vague Tactical Queries** (e.g. *"Were there dangerous moments near goal?"*)
- **Compound Queries** (e.g. *"Passes followed by turnovers in defensive third"*)
- **Negative / Non-Existent Queries** (e.g. *"Second yellow card"*, *"VAR handball review"*)

### Benchmark Empirical Results:
| Metric Category | Metric | Score | Evaluation Findings |
| :--- | :--- | :--- | :--- |
| **Positive Queries** | **Recall@3** | **71.4% (5/7)** | Specific and compound queries retrieved target windows cleanly. Offside query needed top-5 to surface. |
| **Positive Queries** | **Recall@5** | **85.7% (6/7)** | Vague queries (e.g. *"dangerous moments"*) reveal retrieval limits without explicit domain vocabulary. |
| **Non-Existent Queries** | **Hallucination Suppression** | **66.7% (2/3)** | Successfully suppressed fake events for cards/corners; highlighted vector distance thresholds needed for partial keyword overlap ("box"). |

Run evaluation:
```bash
python -m tests.test_retrieval_quality
```

## 🛠️ Limitations & Next Steps

1. **Simplified Offside Proxy (v1 Heuristic)**:
   - *Limitation*: The current offside detector uses a loose frame-window proxy ("attacker positioned ahead of second-to-last defender during a forward pass window"). It does NOT model exact VAR initiation frames, body-part calibration, or touch-line geometry.
   - *Next Step*: Replace proxy heuristic with calibrated pitch geometry and multi-camera bounding box projection.

2. **Synthetic Data Only — Real GSR Integration Pending**:
   - *Limitation*: This pipeline currently runs entirely on synthetic per-frame tracking data generated by `mock_data_gen.py`. Real Game State Reconstruction (GSR) tracking output — from a pipeline performing player/ball detection, multi-object tracking, camera calibration, and jersey number recognition on broadcast footage — is not yet available.
   - *Status*: The GSR pipeline is a **separate, in-progress capstone project** (currently at the research/literature-review stage). Building detection or tracking components inside this repo would be scope creep.
   - *Architecture readiness*: The parser layer (`src/event_extraction/parser.py`) is designed to normalize any input format (JSON, JSONL, CSV) into identical `FrameData`/`TrackedPlayer`/`TrackedBall` instances. When real GSR output becomes available, only the parser needs updating — the downstream preprocessor, heuristics, chunker, and RAG layers require zero changes. A field-mapping reference for the expected real-data contract is available at [`docs/future_work/gsr_field_mapping.md`](docs/future_work/gsr_field_mapping.md).

3. **Synthetic Data Quality vs. Real Tracking Noise**:
   - *Limitation*: Synthetic tracking data has cleaner trajectories than real broadcast camera output, which experiences frequent track ID swaps, stadium camera occlusion, and noisy jersey recognition (~60-70% accuracy). The current preprocessing thresholds (8-frame interpolation gap, 5-frame possession dwell) are tuned for synthetic noise levels and will likely need retuning on real data.
   - *Next Step*: Once real GSR output is available, re-run the preprocessing + heuristics pipeline and report where dwell-time thresholds or interpolation limits produce incorrect events.

4. **Rule-Based Heuristic Scaling vs. ML Classifiers**:
   - *Limitation*: Rule-based thresholds ($d < 1.5\text{m}$, speed $> 3.5\text{m/s}$) require manual tuning for different pitch sizes or match tempos.
   - *Next Step*: Train a Spatial-Temporal Graph Neural Network (ST-GNN) on the SoccerNet tracking dataset to classify complex tactical events directly.
